# 开发任务

本文跟踪 SideNotes 桌面端的开发任务，是判断当前进度的主要依据。

任务状态分为四种：待开始、进行中、已完成、阻塞。只有通过验收标准中列出的验证，任务才标记为已完成；未经验证的部分写入[已知问题](./known-issues.md)。

## 当前版本

0.7.0（预览版）。版本号以 `package.json` 为准，`src-tauri/Cargo.toml` 与 `src-tauri/tauri.conf.json` 同步修改，并在 `src/core/changelog.ts` 最前面补充一条更新日志（单元测试会检查两者一致）。

浏览器预览可单独查看各窗口界面：先运行 `pnpm dev`，再访问 `http://localhost:1420/?window=settings`（设置）或 `?window=capture`（速记）。浏览器预览不连接数据库，仅用于检查界面；加上 `&debug-data=1` 可载入示例记录。

## 验证方法

**与原型比对**：用 Python 启动原型的静态服务（`python -m http.server 5181 --directory docs/prototype`），与 `pnpm dev` 同时运行；分别打开原型的设置弹窗与应用的 `?window=settings`（视口 880×720），逐个分类导出截图、DOM 轮廓（标签、类名、文字与相对坐标）和计算样式后比对。`.claude/launch.json` 记录了这两个预览服务。侧栏比对时，原型视口取 1600×1000，应用取 `?debug-data=1`、视口 416×1000。

用无头 Edge 比对时，每次使用全新的用户数据目录并加上 `--disable-extensions`：本机为 Edge 配置的扩展会自动装入新目录，其中有的会改写页面配色或注入浮层，干扰截图与样式比对。

**桌面端调试**：WebView2 支持远程调试，启动时设置环境变量即可用 DevTools 协议连接三个窗口，检查运行时行为：

```bash
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9555 pnpm tauri dev
```

连接后访问 `http://127.0.0.1:9555/json` 获取各窗口的调试地址。该方式会读写真实的应用数据，验证前应先备份 `%APPDATA%\com.limuhua.sidenotes` 目录下的数据库文件，验证后还原并核对校验值。

需要拦截 IPC 时（例如注入读库失败、阻止写库），用 DevTools 协议的 Fetch 拦截 `http://ipc.localhost/<命令>`，并注意两点：

- 预检请求（OPTIONS）必须放行给 Tauri 自己应答；伪造的响应要带上 `Access-Control-Allow-Origin: *`、`Access-Control-Expose-Headers: Tauri-Response` 与 `Tauri-Response` 头。否则 fetch 失败，Tauri 会改走 postMessage 通道，命令照常发给后端执行。
- 同一时间只在一个窗口开启拦截。多个窗口同时开启时，其它窗口的 IPC 请求可能交给先开启的会话处理。

**窗口行为验证**：窗口层面的效果用系统接口检查。收起时的闪烁用截屏逐帧比对，可从外部切换窗口的 DWM 过渡动画作对照；调宽用 `GetWindowRect` 轮询窗口矩形，并用系统级鼠标输入拖动。用 DevTools 协议模拟指针拖动不可靠：窗口移动后 Chromium 会按真实鼠标位置补发指针事件，打断模拟的拖动。调宽要分别向左、向右拖动，并在松开前按住不动一段时间，确认窗口不再变化。

**隔离的验证版**：桌面端验证可以用独立的应用标识构建一份验证版，数据目录与 WebView2 用户目录都与正式版分开，不必备份真实数据库：

```bash
pnpm tauri build --no-bundle --config '{"identifier":"com.limuhua.sidenotes.verify"}'
```

把 `src-tauri/target/release/sidenotes.exe` 复制到临时目录，设置上文的远程调试环境变量后启动（从以 MSIX 方式安装的程序中启动时，`%APPDATA%` 的写入会被重定向到该程序的 `LocalCache`，涉及路径校验的问题要按实际路径判断）；在侧栏的本地存储中把 `sidenotes:debug-data` 设为 `1` 并刷新，即可载入示例记录。验证结束后删除 `%APPDATA%` 与 `%LOCALAPPDATA%` 下的 `com.limuhua.sidenotes.verify` 目录，再按正常标识重新构建安装包。

**真实按键**：中文输入状态下，系统级按键发送的字母会进入拼音组合，文字应通过 DevTools 协议的 `Input.insertText` 输入，只用系统级按键发送快捷键、回车、Tab、方向键与 Esc。`SendKeys` 等工具发送的按键不带扫描码，页面收到的 `KeyboardEvent.code` 为空，编辑器已按虚拟键码兜底。粘贴不经系统剪贴板验证，以免覆盖用户正在使用的剪贴板内容，改为派发带剪贴板数据的 `paste` 事件（截图可用 `DataTransfer` 放入 `File`，在桌面端同样能走完保存副本的流程）。系统级鼠标与按键可用 PowerShell 调用 `SetCursorPos`、`mouse_event` 与 `keybd_event`（按 `MapVirtualKey` 补上扫描码），坐标按窗口客户区的物理像素计算。
