# 已知问题

本文记录尚未解决的缺陷、未实现的功能和未经验证的事项。解决后从本文删除，并在[开发任务](./tasks.md)中更新状态。

## 未实现

- **列表按需加载**：设置页「其它 › 列表加载」的开关与每批条数会保存，但侧栏目前一次性渲染全部记录，尚未按批追加。
- **更换数据存储位置**：设置页「数据目录」只保存所选位置，不会迁移数据；记录始终保存在应用数据目录。
- **云端自动备份**：设置页只保存服务、地址与账户配置，「云端备份」按钮仅提示尚未接入，不会上传任何数据。
- **检查更新**：「关于」页的按钮只提示更新服务待接入。
- **从资源管理器拖入文件**：Tauri 在 Windows 上接管了窗口的拖放，网页收不到拖入的文件，尚未改用 Tauri 的拖放事件实现；截图与复制的文件可以直接粘贴，也可以用「引用文件」按钮选择。
- **附件清理**：粘贴与引用的文件保存在应用数据目录的 `attachments` 文件夹中，删除记录或清空回收站时不会删除对应的副本。

## 已知缺陷

- **多窗口同时整体写入**：后端保存记录时会整体替换。两个窗口在几毫秒内先后整体写入时，后写入者会覆盖先写入者。正常使用中概率很低，彻底解决需要改为按记录粒度的写入命令。
- **草稿未在窗口间共享**：原型中速记浮窗与侧栏输入卡片共用同一份草稿；桌面端两者的草稿各自保存在窗口内存中，速记浮窗未保存的草稿只在保存记录时写库，退出应用时会丢失。
- **旧的文件引用**：0.7.0 之前写入的文件引用指向原始位置，不会迁移为副本；从卡片只能打开附件文件夹中的副本，点击这些旧引用会提示无法打开，内嵌的本机图片若不在附件文件夹中也不会显示。重新用「引用文件」或粘贴插入即可。
- **浏览器预览的控制台报错**：`pnpm dev` 浏览器预览中，`apply_sidebar_layout`、`hide_sidebar` 等无返回值的桌面命令会抛出「当前环境不支持该桌面能力」的未处理异常。只影响预览时的控制台输出，桌面端不受影响。
- **多屏且缩放不同时的收起轨迹**：贴边一侧还有别的屏幕时（例如左贴边、左侧有副屏），收起平移会让窗口进入相邻屏幕，Windows 按该屏幕的缩放比例重设窗口大小，平移轨迹随之跳动，侧栏也会在相邻屏幕上短暂出现。0.6.8 实测：左侧副屏缩放不同，左贴边收起时窗口宽度由 694 变为 521 个物理像素。右贴边且右侧没有屏幕时不受影响。
- **智能粘贴的代码识别**：没有代码编辑器信息时，按网页格式（pre、等宽字体）与多行文字的特征判断是否为代码，可能误判。需要原样粘贴时按 Ctrl+Shift+V，或撤销后重新粘贴。
- **拖动引用的落点**：文件引用与内嵌图片只能作为单独一行放在段落之间（放到末尾时位于标签之前），不能插进段落中间；也不能拖到新建卡片，或拖到其它页签中的卡片。

## 与原型的已知差异

- **记录分组标题**：原型列表在置顶与普通记录前各有一行分组标题（如「置顶 2」「普通 6」），桌面端尚未实现。
- **标签管理对话框宽度**：原型中对话框在整个页面居中，宽 440 像素；桌面端显示在侧栏窗口内，宽度随侧栏收窄。
- **复制**：原型同时写入纯文本、富文本与图片，提示「已复制文字、富文本和图片表示」；桌面端（菜单首项、卡片上的复制按钮与 Ctrl+C）只写入纯文本，提示「已复制」，多选时为「已复制 N 条记录」。
- **单击与双击**：原型单击卡片进入编辑、双击复制；桌面端按用户反馈改为单击选中、双击编辑，复制改用菜单与 Ctrl+C（复制高亮的卡片），见[技术决策](./decisions.md)第 13 条。
- **新建卡片的位置**：原型 v8 的新建卡片是列表的粘性首项；桌面端按用户要求固定在列表之上，不随列表滚动，见[技术决策](./decisions.md)第 20 条。
- **搜索框输入 #**：原型输入 # 时展开标签菜单；桌面端按用户要求不再展开，改为在输入框中以灰字联想标签。
- **字体与字号**：原型的字体与字号只作用于记录正文，默认 Segoe UI 13px；桌面端作用于全部界面（字号为整页缩放），默认 Maple Mono NF CN 16px，见[技术决策](./decisions.md)第 17、18 条。
- **空白处菜单与标题栏**：原型没有侧栏空白处的右键菜单与双击收起展开；桌面端新增，标题栏不再拖动窗口。单张卡片收起也不再改动修改时间，见[技术决策](./decisions.md)第 19 条。
- **「移出后收起」**：原型只有三个选项；桌面端保留这三个选项，也可以输入 100 至 10000 毫秒。
- **提示文案**：归档后原型提示「已归档，需要时仍能找到」，桌面端为「已归档」；归档写入失败时原型提示「保存失败，原记录未改动。请导出备份后重试。」，桌面端为「操作未保存」。在侧栏新建记录后，原型按所在页签提示「已保存到工作区」「已保存并置顶」或「已保存到归档」并附「查看」，桌面端只提示「记录已保存」。

以下差异为有意保留：

- 原型中展开的标签菜单会被粘性的新建卡片遮住上半部分，桌面端已修正层级，菜单完整显示。
- 原型的提示条显示在侧栏左侧的页面区域，桌面端显示在侧栏窗口底部居中，见[技术决策](./decisions.md)第 9 条。

## 待验证

以下事项无法在当前环境自动验证，需要在桌面端人工确认：

- 设置窗口：按住标题栏拖动窗口；在 Windows 11 下是否为圆角。打开、Esc 关闭、最小化、还原与关闭按钮已通过 WebView2 远程调试验证。
- 设置窗口的「导出备份」写入任意用户选择的目录：依赖对话框插件把所选路径加入文件系统作用域。
- 侧栏出入平移动画：滑入、滑出，以及动画中途反向时是否平滑。
- 经系统剪贴板的操作：从 VS Code、网页复制后粘贴，Ctrl+Shift+V 粘贴为纯文本，截图或资源管理器中复制的文件粘贴到光标处，剪贴板中是网址时按 Ctrl+K，以及 Ctrl+C 复制高亮的卡片。自动验证会覆盖或读取用户正在使用的剪贴板内容，因此只以带剪贴板数据的粘贴事件（截图在桌面端也走完了保存副本与显示的流程）与无头浏览器的剪贴板验证。
- 「引用文件」的系统对话框：桌面端直接调用复制命令验证了副本的写入与引用插入，没有经过对话框本身的选择操作。
- 拖动图片附件到另一张卡片：桌面端只用系统级鼠标验证了拖动文件引用，图片附件在无头浏览器中验证。
