# 技术决策

本文记录影响架构或用户体验的关键决策，说明原因与代价，便于后续维护时判断是否需要调整。

## 1. 侧栏、速记与设置是三个独立窗口

**决定**：侧栏（`main`）、速记浮窗（`capture`）、设置（`settings`）各自是一个 Tauri 窗口，加载同一份前端代码，由 `src/main.tsx` 按窗口标签决定渲染内容。

**原因**：侧栏需要贴附屏幕边缘并在隐藏后完全消失；速记浮窗需要在任何程序之上居中呼出；设置需要能独立移动、最小化，打开时不能把侧栏挤掉或带走焦点。单窗口无法同时满足这些要求。

**代价**：三个窗口各有一份内存状态，需要跨窗口同步，见下一条。

## 2. 跨窗口同步：写库后广播，接收方重新读库

**决定**：

- 任一窗口写库成功后，经 Tauri 事件 `sidenotes://store-changed` 广播。
- 设置变化直接携带新值，其它窗口立即应用；记录或草稿变化由接收方重新读取数据库。
- 窗口获得焦点时再读一次库，兜底错过的通知。
- 读库期间本窗口若又写入过，丢弃这次读到的结果，避免把新数据回退成旧快照。
- 设置改用 `save_settings` 单独写入，界面先应用新值，约 120 毫秒内的连续修改合并为一次写入；写入失败时回滚到最后一次成功的设置。

**原因**：后端的 `save_snapshot` 会先清空再整体写入记录。此前各窗口只在启动时读库一次，设置窗口改一次设置，就会用启动时的旧记录覆盖侧栏里新写的内容，造成数据丢失。

**代价**：两个窗口在几毫秒内同时整体写入时，后写者仍会覆盖先写者。正常使用中用户同一时刻只操作一个窗口，概率很低；彻底解决需要改为按记录粒度的写入命令，见[已知问题](./known-issues.md)。

## 3. 设置窗口即原型的设置对话框

**决定**：设置窗口为无边框窗口，窗口内容直接渲染原型的 `.modal.settings-modal`，DOM 结构、类名与文案逐项对照原型 `settings.js`，样式全部复用 `prototype.css`。标题栏承担窗口拖动，并在关闭按钮旁补充最小化按钮。窗口默认按原型桌面端的 880×720 网页像素打开，保留对话框的 1px 边框，只去掉圆角、投影与弹出动画。0.6.9 起窗口可以拖动边缘调整大小，最小 720×560 网页像素；设计尺寸与最小尺寸都乘以系统文本缩放比例（页面像素比与窗口缩放比例之比）换算为窗口尺寸，再次打开时沿用调整后的大小。

**原因**：设置页需要与原型一比一一致。使用系统原生标题栏会多出一条与原型无关的标题栏，且无法复用原型对话框的头部样式。880 像素宽于原型最小断点 801 像素，可以命中与大屏浏览器完全相同的样式规则；保留 1px 边框后，内容区尺寸与原型逐像素一致。Windows 的文本缩放会让网页内容整体放大：125% 时 880×720 的窗口在网页里只有 704×576，「侧栏」一行的下拉框文字被箭头遮住，靠后的设置项也显示不全，所以窗口尺寸要按文本缩放换算。

**代价**：窗口圆角与投影依赖系统：Windows 11 会自动加圆角，Windows 10 为直角。窗口窄于 801 网页像素时仍按大屏布局排列（见第 7 条），为此「侧栏」分组首行的三列改为不窄于内容；最小宽度以各分类都不截断、不重叠为准。系统按整个窗口（含不可见边框）限制最小尺寸，设定时补上边框与内容区的尺寸差。

## 4. 侧栏出入动画由后端移动真实窗口

**决定**：侧栏显示与收起时，由 Rust 在后台线程按帧移动窗口位置（easeOutCubic），时长取设置中的「出入动画」，默认 260 毫秒，设为 0 关闭动画。每次显示或隐藏都会递增动画代次，旧动画据此立即停止，新动画从窗口当前位置继续。

**原因**：侧栏窗口贴在屏幕边缘，只在网页内做 CSS 位移时，窗口边缘本身不动，看不出平移效果。

**代价**：动画期间每帧调用一次窗口定位，有少量系统开销。

## 5. 设置项与默认值以原型为准

**决定**：设置页的条目以原型为准。「边缘唤出」开关不在设置页提供，默认开启；「出入动画」是用户明确要求可配置的项目，作为侧栏卡片的第三行加入，沿用「宽度」行的样式。默认值同样取原型：侧栏宽度 416 像素，记录字体 Segoe UI。

**原因**：设置页需要与原型一比一一致，新增条目会破坏布局与对齐。已保存的设置不受默认值变化影响。

## 6. 构建与版本号

**决定**：

- Vite 8 起压缩由 Oxc 承担，不再配置 `minify: 'esbuild'`，否则需要额外安装已废弃的 esbuild。
- 界面上的版本号由 `vite.config.ts` 读取 `package.json` 注入 `__APP_VERSION__`，不在组件里手写。
- 示例数据只在调试开关打开时载入（`?debug-data=1` 或本地存储 `sidenotes:debug-data` 为 `1`），正式运行不写入用户数据库。

## 7. 桌面窗口不套用原型的窄屏规则

**决定**：构建时由 `vite.config.ts` 中的 PostCSS 插件移除 `prototype.css` 里按视口宽高生效的媒体查询，`prefers-reduced-motion` 等偏好类查询保留。原型样式文件本身不做改动。

**原因**：原型是在大屏浏览器中展示的页面，侧栏只是其中一个 416 像素宽的面板，原型里的窄屏规则（如 `max-width: 480px`）面向小屏浏览器。桌面端的侧栏窗口本身就只有面板宽，若保留这些规则，侧栏会整体套用原型的窄屏布局，内边距、字号与间距都与原型不一致。移除后，各窗口的样式与原型在大屏浏览器中的表现一致。

**代价**：设置窗口在屏幕很小、窗口被迫缩到 800 像素以下时，不再切换为原型的窄屏布局。

## 8. 修正原型中标签菜单被遮挡的层级

**决定**：桌面端把侧栏列表顶栏的 `z-index` 从 6 提高到 13，高于粘性新建卡片的 12。

**原因**：原型 v8 为新建卡片加入粘性底板后，展开的标签菜单上半部分会被新建卡片遮住，选中项与「全部标签」均不可见。这是原型的层级缺陷而非设计意图，顶栏中只有菜单会越出自身范围，调整层级不影响其它布局。

## 9. 提示条在窗口内居中

**决定**：桌面端各窗口的提示条在窗口底部居中，距底部 18 像素。提示区按内容取宽度，上限为窗口宽度减 28 像素，仍用 `translateX(-50%)` 平移居中。

**原因**：原型的提示条位于侧栏左侧的页面区域，桌面端窗口没有这块区域。固定定位元素设置 `left: 50%` 后，自适应宽度最多只有视口的一半，侧栏窗口中「已移入回收站」这类提示会折成两行，所以宽度改为按内容计算。居中方式与原型相同，提示条内部的渲染与原型逐像素一致。

**代价**：提示条会盖住列表底部的一小块区域，按原型的时长自动消失。

## 10. 窗口在后端就绪后创建，读到数据库前不写入

**决定**：

- `tauri.conf.json` 中三个窗口均设为 `create: false`，由 `setup` 在 `app.manage` 之后按配置创建。
- 前端首次读库失败时按 200、500、1000 毫秒间隔重试三次；仍失败则进入「读库失败」状态，列表为空并给出提示，此时拒绝一切写入（记录、草稿、设置）与导出备份。窗口获得焦点、收到其它窗口的写库通知，或在设置中点「重试本地保存」时重新读库，读到后恢复正常。

**原因**：Tauri 2 先创建配置中的窗口，再运行 `setup`。页面加载完成时后端状态可能还没有注册，`load_snapshot` 会失败（「state not managed」）。0.6.5 正式版冷启动 8 次，侧栏窗口 8 次都读库失败，以空列表和默认设置启动。后端保存记录时整体替换，此时在侧栏保存一条记录，就会把数据库中的其它记录全部删掉，设置也会被默认值覆盖。前端拒绝写入是第二道防线，覆盖数据库被占用、文件损坏等其它读库失败的情况。

**代价**：读库失败期间无法保存，草稿只保留在窗口内存中。

## 11. 侧栏窗口的隐藏、调宽、贴边与设置弹窗

**决定**：

- 侧栏窗口创建后通过 `DwmSetWindowAttribute` 关闭系统的显示与隐藏过渡动画。
- 拖动边框调整宽度时，用指针的屏幕坐标计算位移，并按「页面像素比 / 窗口缩放比例」换算为窗口逻辑像素；宽度按 4 像素取整，离当前宽度不足 3 像素时不改动。后端用一次 `SetWindowPos` 同时设置窗口位置与尺寸。
- 贴边与收起位置按内容区计算，再减去窗口外框到内容区的偏移，换算成窗口位置。
- 鼠标移出与窗口失焦都安排收起，到点时再按最新状态判断：仍需保持展开（固定、菜单、对话框、拖动、多选，以及「编辑时保持展开」开启时的编辑、整理标签与新建卡片的未保存内容）时记下「待收起」，这些条件解除后补一次收起；鼠标仍在侧栏上时不收起。
- 到点时设置窗口正在显示（可见且未最小化）则不收起，每 400 毫秒复查一次，设置窗口关闭后再收起。
- 卡片菜单在点击菜单之外与窗口失焦时关闭。

**原因**：

- 侧栏收起时先平移到屏幕外、隐藏，再把窗口挪回贴边位置备用。Windows 为隐藏播放的淡出动画出现在挪回后的位置：平移结束约 90 毫秒后，侧栏会在原处闪现并淡出。
- 调宽时窗口本身在移动，用窗口内坐标计算位移会与窗口位置互相反馈；分两次设置尺寸与位置，每帧还会先在原位改宽再移动，两者叠加成抖动。Windows 的文本缩放会让页面像素与窗口逻辑像素不一致，需要换算。窗口移动后浏览器会按新位置补发指针事件，屏幕坐标可能有 1 像素的舍入差，恰在取整边界上时会来回跳一档，所以取整时留出余量。
- 带阴影的无边框窗口保留了不可见的边框（150% 缩放下左右各 11、顶部 2 个物理像素），按外框贴边时内容区会超出屏幕边缘。
- 原型的设置是侧栏之上的弹窗，打开期间侧栏不会收起；桌面端设置是独立窗口，打开时侧栏失焦，鼠标也可能移到设置窗口上。设置窗口关闭时侧栏收不到任何事件，此前只在到点时判断一次，关闭设置后鼠标若已在别处，侧栏就一直停留。
- 点到侧栏窗口之外时页面收不到按下事件，只会失焦；此前菜单因此一直开着，失焦处理又因「菜单开着」直接跳过收起，两者互相卡住。

**代价**：关闭过渡动画只影响侧栏窗口，Windows 以外的平台没有对应处理，调宽退回分步设置。不可见边框仍是窗口的一部分：右贴边时右侧边框落在屏幕之外，左侧边框紧挨内容区左边。

## 12. 卡片手势按原型 interactions.js 移植

**决定**：长按排序、框选与多选在 `useCardInteractions` 中实现，逻辑、阈值与提示文字逐项对照原型：按住 300 毫秒开始拖动，停在页签上 240 毫秒切换，空白处移动 4 像素开始框选；手势在 document 捕获阶段处理，优先于卡片的单击选中与双击编辑。拖动中跟随指针的卡片、插入线与框选矩形是挂在 body 上的临时元素；卡片、页签的状态类经 React 状态下发。新建卡片与原型一样放在记录列表内作为粘性首项，不参与手势。0.6.9 起同一套手势还负责拖动图片附件与文件引用，见第 16 条；拖动途中按 Esc 取消。

**原因**：原型用捕获阶段的监听保证手势优先于卡片自身的点击；临时元素随指针每帧移动，用 React 渲染会频繁重绘整个列表。卡片与页签由 React 渲染，若直接修改它们的类名，会在下一次渲染时被覆盖。

## 13. 双击编辑、右键菜单与失焦保存

**决定**：

- 单击卡片只选中（获得焦点），双击进入编辑；Enter 也可进入编辑。复制放在记录菜单首项，选中卡片后按 Ctrl+C 复制整条记录，卡片上的复制按钮保留。
- 卡片右键打开记录菜单；输入框、编辑区与选中的文字保留系统菜单（剪切、复制、粘贴），其余位置不弹出浏览器菜单。
- 编辑中焦点离开整张卡片即保存并回到预览，对应原型 `scheduleEditBlur`：焦点交接完成后再判断，仍在卡片内（工具按钮）时不提交；切换到其它窗口时页面焦点仍留在卡片里，编辑保持不变；附件读取期间不提交。内容与附件都没变时退出编辑不写库。
- 编辑中的卡片使用强调色边框、外圈与投影，其余卡片与新建卡片变淡；新建卡片未聚焦时去掉光晕。卡片菜单底色比卡片略灰、投影更重，所属卡片同时高亮。

**原因**：原型「单击编辑、双击复制」在桌面端容易误入编辑，用户反馈不舒服；双击编辑与系统文件管理器、多数笔记软件一致，选中加 Ctrl+C 是桌面用户熟悉的复制方式。右键菜单是原型 `note-menu.js` 已有的入口，迁移时遗漏。新建卡片始终带光晕时，与编辑中的卡片同时出现会分散视觉重点。

**代价**：单击不再直接进入编辑，需要双击或按 Enter。

## 14. Markdown 编辑命令作用于原文

**决定**：格式快捷键、回车续写与智能粘贴都实现为纯函数（`core/markdown-commands.ts`）：输入原文与选区，返回新的原文与选区，由编辑器写回、重排并记入撤销历史，每次修改一步撤销。快捷键参照 Typora，按物理按键识别（`KeyboardEvent.code`），缺少按键位置时按虚拟键码兜底；输入法组合期间不处理。智能粘贴：选中文字后粘贴网址生成链接；网页复制的单个链接保留文字与地址；来自 VS Code（剪贴板中的 `vscode-editor-data`）或网页格式为 pre、等宽字体，以及特征明显的多行纯文本包进代码块；光标在代码中时一律纯文本；Ctrl+Shift+V 粘贴为纯文本。标签联想的灰字是不参与原文映射的装饰节点，联想显示时 Tab、上下键与 Esc 在窗口捕获阶段处理，先于侧栏的全局快捷键。

**原因**：编辑器以原文为唯一数据源，命令只改原文才能与撤销、重排、选区恢复保持一致，也便于单元测试。按物理按键识别避免中文输入法、键盘布局改变按键字符；部分输入来源不带扫描码，需要兜底。

**代价**：代码识别靠特征判断，可能误判，可用 Ctrl+Shift+V 或撤销后重新粘贴。

## 15. 正式版可以打开开发者工具

**决定**：启用 Tauri 的 `devtools` 特性，设置「关于 › 调试」提供按钮，分别打开侧栏、速记浮窗与设置的开发者工具。

**原因**：用户需要在正式版中排查界面问题；桌面端已不再弹出浏览器右键菜单，原来的「检查」入口随之消失。

**代价**：正式版用户也能打开开发者工具查看页面结构与本地数据，预览阶段可以接受。

## 16. 图片与文件引用在卡片之间拖动

**决定**：

- 沿用卡片手势：按住图片附件、文件引用或内嵌图片，移动超过 6 像素或按住 300 毫秒开始拖动，单击仍是放大或打开。
- 解析器为图片与文件引用记录在显示正文中的位置、为块级元素记录所占的行；卡片显示正文去掉了标题行与行尾标签，按 `core/display.ts` 的规则换算回原文（行号加上标题所占的行，列不变）。
- 图片附件落在目标卡片的图片之间；正文引用作为单独一行插在段落之间，放到末尾时位于标签之前；换算出的片段必须正好是一个引用或文件路径，否则放弃，避免误删。两条记录一次写入，提示条提供撤销。

**原因**：Tauri 在 Windows 上默认接管窗口的拖放，网页内的 HTML5 拖放不可用，所以用指针事件实现；解析器给出的位置是唯一能准确对应原文的依据，按文字搜索在同一记录有多个相同引用时会错位。

**代价**：引用只能放在段落之间，不能插进段落中间；不能拖到新建卡片或其它页签中的卡片。
