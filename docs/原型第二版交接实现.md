# 原型第二版交接实现

更新日期：2026-11-16。

本文把交互原型第二版交接给桌面应用的实现，内容包括：原型改了什么，桌面端要做什么，哪些事只能在桌面端验证，哪些还没定。原型第二版包括两部分：[交互原型](./prototype/README.md)（页面上标为 0.7.4），以及它依据的[设计系统](./design-system/DESIGN.md)。这些工作在 `design-system` 分支上完成，对应任务 DS01–DS10、技术决策 DS-1–DS-16，经过了用户九轮标注反馈。桌面应用当前是 0.7.3，还没有这些改动。交接时 `design-system` 合并到 `claude`：桌面端在 `claude` 上实现，设计继续在 `design-system` 上迭代，两个分支的分工与同步见第九节。

## 一、以什么为准

- **界面与交互以原型为准。** 原型的当前行为是九轮反馈的最终结果。[任务](./tasks.md) DS05–DS10 的验收清单按轮次记录，后一轮会改掉前一轮的部分做法。例如，第五次反馈把搜索框移到筛选行，第六次又移回页签栏。所以以最后一轮为准。原型与规范、验收清单有出入时，先问用户。
- **桌面能力以 0.7.3 为准。** 下面这些原型只在浏览器中模拟：数据目录与迁移、快照、导出备份（含附件）、附件副本、从资源管理器拖入、快捷键的录入与全局注册。见[已知问题](./known-issues.md)「交互原型的附件只能在浏览器中模拟」「交互原型的快照与云端备份」。实现时保留桌面端现有的做法，只按原型改界面与操作。
- **浏览器限制下的写法不搬到桌面端。** 例如图片写成 `sidenotes-image:` 引用并随记录保存，文件引用只在本次会话中可用，快照存在浏览器本地存储里。
- **设置页先对照再改。** 设置页的字号，以及「数据与同步」一行一项的布局，是用户要求的规范（[技术决策](./decisions.md)第 31、32 条）。设计系统的设置布局也照搬 0.7.3。实现时逐页对照原型，与这两条有出入时先问用户。

## 二、怎么看原型

在仓库根目录执行：

```bash
pnpm playground
```

原型在 `http://localhost:1430/prototype/`，Playground 在 `http://localhost:1430/design-system/playground/`，两边可以互相跳转。

- 开发与预览的进程由实现桌面端的对话自己启动和关闭：`pnpm tauri:dev` 运行桌面应用，`pnpm playground` 打开原型与 Playground。`.claude/launch.json` 中的 `app` 在 1420 端口运行 `pnpm dev`，`playground` 在 1430 端口运行原型与 Playground。
- 新存档有 46 条示例记录，默认固定 6 个标签。侧栏窄时页签栏放不下，可以直接看末格与搜索分组。
- 原型每轮改了什么，见[原型说明](./prototype/README.md)；验证做到了哪一步，见 [VALIDATION.md](./prototype/VALIDATION.md)。

## 三、关键变更

以下变更都相对 0.7.3。括号里是详细规则所在，「DS-n」指[技术决策](./decisions.md)中的条目。

### 3.1 主题与设置

- 五套主题取代四种界面材质：终端（默认）、杂志、记录纸、Windows 11、磨砂玻璃，每套都有浅色与深色。
  - 颜色、字体、尺寸、圆角、材质与动效都来自[设计令牌](./design-system/design-tokens.md)，文件在 `docs/design-system/tokens/`。
  - 令牌表达不了的 6 项结构差异写在根节点的 `data-sn-*` 属性上，定义在 Playground 的 `src/surfaces.ts` 与原型的 `surfaces.js`。
  - 组件不区分主题。见 [DESIGN.md](./design-system/DESIGN.md) 与[五套主题](./design-system/themes/terminal.md)。
- 设置结构升到版本 3。迁移规则见 [adaptation.md](./design-system/adaptation.md) 第八节，原型的实现见 `app.js` 的 `normalizeSettings`。
  - `surface` 的 `standard` 迁移为 `terminal`，无法识别的取值回到终端。
  - 字体增加「跟随主题」并作为默认值，用户选过的字体保留。
  - 字号 8–24、步长 0.5、默认 12，作用是整页缩放（界面按 13px 设计）。侧栏默认宽 400。
  - 新增四项设置：
    - `appIcon`：应用图标。
    - `pinnedTags`：固定为页签的标签，按页签栏的顺序保存。
    - `windowTabs`：记录窗口的标签页在顶部还是左侧，默认左侧。
    - `scrollOnEdit`：进入编辑时把卡片滚到列表顶部，默认打开。
  - 去掉「编辑时保持展开」，编辑期间一律保持展开。
- 应用图标：6 个内置图标与上传的图片，默认 211「门缝浅笑 · 靛蓝」。
  - 资源已随应用打包，在 `src-tauri/icons/builtin/`，由 `pnpm icons` 生成。
  - 桌面图标已换成 211，但桌面应用还不能切换（DS-5，adaptation.md 第十节）。

### 3.2 侧栏

- 侧栏自上而下分为标题区、页签栏、筛选行、新建卡片、列表、底栏（[layout.md](./design-system/layout.md) 第二节，[components.md](./design-system/components.md) 第一节）。
  - 新建卡片的工具栏一直显示。
  - 底栏左下角是版本号，有新版本时带角标；存储状态只在出错时显示。
- 页签由随记、置顶与用户手动固定的标签组成（DS-11，[interactions.md](./design-system/interactions.md) 第十二节）。
  - 去掉归档，旧的归档记录回到随记并加上 #归档。随记显示没有已固定标签的记录。
  - 固定页签有两个入口：筛选行的「固定为页签」，以及最后一格菜单里的「新建页签」。页签不会自动出现。
  - 双击页签改名，所有记录上的这个标签一起改。按住页签可以拖动排序。右键「移出页签栏」可以撤销。
  - 卡片拖到标签页签上，加上这个标签；拖到随记，去掉当前页签的标签；拖到置顶，只置顶。在标签页签中新建的记录带上这个标签。
  - 页签上不写 #，条数只写在随记与当前页签上。
- 页签栏的排布（DS-13–DS-15）：
  - 放得下时全部显示，最后一格是「+」。
  - 放不下时，最后一个显示的页签与「N ▾」合成末格。从菜单选页签只换末格里的页签，前面的不动；切换页签时页签栏不变。空间不够时，先不写当前页签的条数，再缩短末格页签的名字。
  - 算法在原型 `tabs.js` 的 `layout` 与 `src/core/tabLayout.ts` 的 `fitTabs`，测试在 `src/core/tabLayout.test.ts`。T78 把它们从 Playground 搬进 `src/core`，Playground 从这里引用。
- 筛选行（DS-12–DS-14）：
  - 左边平时是标签下拉。
  - 按标签筛选时，左边是「# 产品 · 2 条 ×」与「固定为页签」「合并」。
  - 搜索时，左边是结果条数。
  - 有选中的卡片时，左边是「已选 N 条」「合并」「移入回收站」。
  - 右边是多选与收起/展开全部。
- 列表上下边缘渐隐 16px，只在那一侧还有内容时出现。遮罩加在滚动容器上，由滚动驱动的动画（`animation-timeline: scroll(self)`）给出，WebView2 支持这种动画（DS-16）。磨砂玻璃的列表只纵向滚动。

### 3.3 记录卡片与选中

- 卡片的布局（components.md 第二节）：
  - 时间与操作按钮共用标题行右侧，悬停或选中时操作换下时间。
  - 标题最多两行。底部一行只在有标签时出现。
  - 置顶按钮排第一，最右是收起按钮。
- 悬停与选中共用一种高亮：主题强调色加一像素外圈，终端的标题栏同时染色。置顶卡片默认带淡的强调色边框。编辑中的卡片只有一圈强调色边框（[editing.md](./design-system/editing.md)）。
- 单击选中，双击编辑。选中按资源管理器的习惯（DS-14，interactions.md 第二节）：
  - 单击只选这一张。
  - Ctrl+单击时，上一次单击的那张一起选上。
  - Shift+单击时，从上一次单击的那张选到这一张。
  - 多选按钮按下时，卡片的图标换成勾选框，快捷按钮隐藏，单击就是勾选。
- 键盘（interactions.md 第三节）：
  - ↑ ↓ Home End 移动，Enter 编辑，Delete 移入回收站，Shift+F10 打开卡片菜单，Ctrl+C 复制，Ctrl+, 打开设置。
  - Esc 依次关闭菜单与弹窗、取消拖动、退出编辑、收起有内容的输入、清除多选、清空搜索，最后收起侧栏。

### 3.4 搜索

- 搜索框在页签栏最右端。点放大镜或按 Ctrl+F 时，搜索框从右向左盖住页签，收起是展开的倒放。框里只有输入框与清空按钮（DS-13）。
- 搜索范围与结果（DS-12、DS-14）：
  - 搜索全部记录（不含回收站），与当前在哪个页签无关。
  - 结果按页签分组，置顶组在最前。组标题右侧与卡片菜单都有「转到」，切到所在页签，滚到这条并闪一下。
  - Esc、清空或「转到」结束搜索，回到原来的页签、标签筛选与滚动位置。
- 匹配规则（DS-15）：
  - 不带 # 的词只搜标题、正文与附件名。
  - 带 # 的词只搜标签。写完整的已有标签时只搜这个标签，没写完时按前缀匹配。
  - 两种写法可以同时用：「开发 #发布」找正文提到「开发」、并且带 #发布 的记录。
  - 命中的文字高亮，不带 # 的词不在标签上高亮。
  - 不带 # 的词正好是已有标签时，条数后面出现「#开发 N 条」，点一下改为搜这个标签。
- 规则的纯函数可以直接搬：Playground `src/model/notes.tsx` 的 `matchesSearch` 与 `wordTag`，以及 `src/ui/searchHighlight.ts`。测试在 `docs/design-system/tests/search.test.ts`。
- 搜索框的占位文字还没定，见第六节。

### 3.5 整理与提示

- 合并成一条（DS-11，interactions.md 第十三节）：
  - 入口有三个：筛选行的「合并」、多选后右键「合并成一条…」、多选后右键其中一张「合并到「标题」」。
  - 共同标签作标题，其余标签各成一个二级小节。只有一行的记录合成待办，多行的整段放入。标签取并集。
  - 弹窗有格式选择、实时预览与「保留原记录」。原记录移到回收站，提示条一次撤销全部恢复。
  - 规则在 Playground `src/model/merge.ts`，测试在 `merge.test.ts`。
- 移入回收站不再确认，提示条可以撤销；多选时作用于全部选中的记录。永久删除与清空回收站仍要确认（DS-12）。
- 提示条出现在操作所在的窗口里，侧栏、设置窗口、速记浮窗各有自己的提示条。指针停留或获得焦点时暂停计时。连续收起/展开全部只留最新的一条（DS-14）。
- 新记录不在当前页签时，提示「已记在「X」」并可「查看」。在标签页签中去掉新建卡片上的「#标签」后保存，还可以「放回」（DS-12）。

### 3.6 编辑与附件

这一组有一部分是原型向 0.7.3 看齐，桌面端要逐条核对，已有的不重做。

- 列表与待办的项头不随光标露出，光标不停在项头之前。在正文开头按退格，删去项头。
- 双击卡片进入编辑时，光标在正文末尾、标签行之前。
- 附件插在光标处，标签行始终在最后。
- 编辑面中拖动图片与文件时，落点精确到字符。拖影的左上角跟着指针，垫在文字下面（DS-10–DS-12）。
- 附件弹窗（DS-10、DS-11）：
  - Markdown 原文显示在整行的大输入框里，点「应用修改」或按 Ctrl+Enter 才写入。
  - 文件附件不显示预览。

### 3.7 记录窗口（桌面端新增）

- 两个入口打开同一种窗口：卡片拖出侧栏，在松开的位置打开；或点「展开全文」。窗口可以移动、缩放与置顶，大小按内容决定（DS-10）。
- 标签页：
  - 下面三种操作都会合并成标签页：卡片拖到已开的窗口上，窗口标题栏拖到另一个窗口上，标签页拖到另一个窗口。
  - 标签页拖到窗口外，拆成新窗口。
  - 标签页可以在顶部，也可以在左侧竖排，默认左侧。窗口上的按钮与设置中的同一项都能切换。
  - 有标签页时，窗口按标签页定宽，上限 720。
- 动效：
  - 打开与关闭呼应。拖出的窗口从倾斜的拖影展开、摆正后落定，关闭时缩回原来的卡片；「展开全文」打开的窗口关闭时原路滑回。
  - 获得焦点的窗口，边框带一点强调色。置顶时图钉是实心的。
- 按键：
  - Esc 关闭当前标签页，只剩一个时关闭窗口；Shift+Esc 关闭整个窗口。
  - 「关闭全部记录窗口」默认 Alt+Shift+W，可以在设置中更换。
  - 桌面端补上 Ctrl+W 关闭当前页，Ctrl+Shift+W 与 Alt+F4 关闭窗口。这几个组合在浏览器中被占用，原型没有。
- 原型中的窗口是页面里的浮层（`note-window.js`），位置、大小与标签页都不保存。桌面端要用独立的 Tauri 窗口（DS-8–DS-11，已知问题「记录窗口只在交互原型中实现」）。

### 3.8 速记浮窗与设置窗口

- 速记浮窗（components.md 第四节）：
  - 快捷键与 Markdown 的说明收进标题旁的问号。
  - 字数在附件工具右边，不显示草稿状态。
  - 磨砂玻璃主题下，浮窗是一整块玻璃。
- 设置窗口的整体布局：880 × 560，高度固定，左右两栏只靠底色区分。页面有最大宽度，内容多的分类在页面里滚动（DS-10、DS-11，components.md 第五节）。
- 设置窗口的控件：
  - 同一行的设置项之间有竖线。
  - 问号说明只留给需要额外理解的项。
  - 滑块、数值框与数字组合框可以用滚轮调整，按住 Shift 加大步长。
  - 路径只占一行，悬停看全文，双击复制。
- 设置窗口的各分类：
  - 外观与交互：明暗模式与主题两行卡片（预览是迷你侧栏）、应用图标、字体、字号。「其它」固定两行，第一行是窗口标签页、通知位置，第二行是列表加载、整理提醒。
  - 快捷键：分为全局、应用内、格式三组，新增「关闭全部记录窗口」。
  - 回收站：保留天数紧跟条数，按搜索快捷键聚焦搜索框。
  - 关于（DS-14）：
    - 「检查更新」在版本号旁。
    - 项目一行加「AGPL-3.0」。
    - 开源致谢只列实际用到的组件与许可证：Tauri、React、Vite、TypeScript、SQLite、rusqlite、serde、windows-rs、Maple Mono。
    - 调试只留「打开开发者工具」。
- 调整侧栏宽度的手柄，在指针停留 400ms 后才高亮。

## 五、只能在桌面端验证的事项

原型与 Playground 在浏览器中验证，多数操作用脚本派发的事件完成。下面这些要在 Tauri 与 Windows 中，用真实的鼠标、键盘与触控板确认。已知问题的「设计系统」一节逐条列出了这些事项。

## 八、注意事项

- **用户最看重的设计规则**（DS-8 及历次反馈）：
  - 避免不必要的二次标签和描述，让布局来解释。
  - 提示浮窗只写最客观的操作。
  - 按钮、卡片与标题区不加悬停提示，名称只写在 `aria-label` 中，悬浮说明只跟问号绑定。
  - 输入框获得焦点时只在底边换成强调色线，不加框；编辑中的卡片保留卡片的高亮。
  - 关闭是打开的倒放；拖动时要看得出拿起的是什么、会落在哪里。
  - 组件太宽或太高时，先查整页的布局，不只缩小组件。
- **产品样式只引用令牌。** `docs/design-system/tests/` 中的 `styles.test.ts` 与 `prototype.test.ts` 检查 Playground 与原型的样式（规则在 `css-rules.ts`），不允许写死颜色、像素、rem 与时长；确实要写固定值时，在行内注释写「固定：原因」。桌面端的样式至少纳入其中一项：只能引用令牌表中有的令牌（见第九节）；其余几项是否纳入，实现时决定。
- **测试范围。** `pnpm test` 同时运行桌面应用与设计系统的测试，`pnpm typecheck` 与 `pnpm lint` 也覆盖 Playground。
- **不改参考实现。** 令牌、原型与 Playground 的设计只在 `design-system` 上改，实现桌面端时不改它们，需要新令牌时先问用户。`src/core` 的改动让 Playground 编译不过时，只做为了能编译的最小改动，不改设计。发现原型本身有问题，先问用户。
- **0.7.3 中被第二版取代的做法：**
  - 筛选条，由筛选行取代。
  - 绿色的选中高亮，改为各主题的强调色。
  - 工作区、置顶、归档三个页签，改为随记、置顶与固定的标签。
  - 编辑中的卡片原来用强调色边框、外圈与投影，其余卡片变淡；改为只有一圈强调色边框。
  - 设置窗口 880 × 720，改为 880 × 560。
  - 四种界面材质，改为五套主题。
- **同步清理文档。** 已知问题中有两类条目要随实现更新：
  - 「与原型的已知差异」一节比较的是第一版原型。原型第二版吸收了其中一部分，实现时逐条核对，过时的删掉。
  - 「设计系统」一节中「桌面应用还没有第 N 次反馈的改动」等条目，实现一项删一项。
- **编译路径。** 在 OneDrive 下的工作树里运行 `cargo build`，可能报 `output path is not a writable directory`。把 `CARGO_TARGET_DIR` 设到 OneDrive 之外即可（已知问题「工作树内编译失败」）。

## 九、两个分支的分工与同步

设计与应用分在两个分支上，2026-11-16 交接时两者一致（[技术决策](./decisions.md) DS-17）。

| 分支 | 工作树 | 改什么 |
| --- | --- | --- |
| `design-system` | `SideNotes-Design` | 令牌、原型、Playground 与设计文档 |
| `claude` | `SideNotes` | 桌面应用 |

- **令牌只有一份。** 桌面端直接引用 `docs/design-system/tokens/`，同一个分支里原型、Playground 与应用用的是同一份令牌。在 `design-system` 上改令牌不影响 `claude` 上的应用，合并时才进入应用。
- **两个方向都有依赖。**
  - 应用依赖令牌：令牌的值变了，应用的外观跟着变，这是预期中的；令牌改名或删除，应用的样式就会失效。所以 `src/styles/` 纳入令牌检查，样式里只能用令牌表中有的令牌，合并后测试会报错。
  - Playground 依赖应用的代码：`src/core` 的 types、tags、notes、settings 等被 Playground import 了 50 多处。`claude` 上改这些模块时，Playground 可能编译不过，只做为了能编译的最小改动，不改设计。
- **同步的顺序：**
  1. `design-system` 上开始新一轮调整之前，先把 `claude` 合并进 `design-system`，让设计分支用上最新的应用代码。
  2. 这一轮设计确认后，把 `design-system` 合并进 `claude`。
  3. 合并后在 `claude` 上运行 `pnpm typecheck`、`pnpm lint`、`pnpm test`，并在桌面端看一遍外观。
