# 待人工手动确认事项

只列我在这台电脑上测不了、要你动手的事：要你的账户、密钥或设备，平常用应用时又不一定碰得到。确认过、改掉或用不着的项随时删掉；平常用着发现的问题直接告诉我，不必等这份清单。

## 一、失败通知邮件（T163）

要你的 Resend 密钥。

1. 设置 → 数据与同步 → 云端同步，点「失败通知」后面的信封按钮，填收件邮箱与 Resend 密钥，点「发送测试邮件」：弹窗里显示已发出，邮箱里收到测试邮件。保存后打开「失败通知」。
2. 让同步失败一次（例如在 NAS 上去掉 `/backup/Test` 的写入权限）后点「立即同步」：弹出系统通知，邮箱里收到「云端同步失败」的邮件。

## 二、发布 Google 的同意屏幕（T173）

登录、同步与恢复已经用测试用户测过；发布之前，测试用户以外的账户登录不了，登录 7 天后失效。

重做的官网（T178）已于 2026-11-23 上线，现在可以提交：在品牌页的「Branding verification issues」里选「I have fixed the issues」，点 Proceed；通过后到[受众页](https://console.cloud.google.com/auth/audience)点「发布应用」。

## 三、Google 换成「桌面应用」类型的客户端（T183）

现在的客户端是「Web 应用」类型，换令牌必须带密钥，密钥在仓库里被 GitHub 与 GitGuardian 报为泄露。「桌面应用」类型不用密钥。

1. 在同一个项目的[客户端页](https://console.cloud.google.com/auth/clients)新建 OAuth 客户端，类型选「桌面应用」，名称填 SideNotes；把客户端编号（不用密钥）发给我。同意屏幕、测试用户与品牌验证都按项目算，不用重做。
2. 我实测不带密钥能登录、同步后，你删掉旧的「Web 应用」客户端（旧密钥随之作废），再把 GitHub「Security → Secret scanning」里的两条提醒与 GitGuardian 的那条标为已撤销（Revoked）。
